## Confirmed defects and repairs

1. **Failed and fixed, then reverified — legacy PMS tenant boundary.** A tenant-1 administrator and a manager assignment could access an organization-2 legacy project. can_access_project now checks the canonical tenant before global/manager/member grants for projects outside workspaces; accessible_project_query applies the same boundary. Explicit workspace sharing remains controlled by workspace membership. Regression: test_pms_legacy_project_tenant_boundary_applies_before_global_role_and_membership.
2. **Failed and fixed, then reverified — linked SRM financial payload.** A task contributor with no financial permission could obtain an engagement budget through GET /project-management/projects/{id}, despite billing correctly returning 403. Linked engagement/order/contract/billing-plan payloads now require SRM engagement permission, record visibility and tenant filters. Regression: test_pms_task_access_does_not_expose_srm_commercial_payload.
3. **Failed and fixed, then reverified — ineligible project assignment.** POST project members accepted a foreign-tenant user and inactive user. New assignments now require an active local-tenant user, or existing membership in the specific workspace for a workspace project. Historical memberships are retained. Regression: test_project_member_creation_rejects_foreign_and_inactive_users.
4. **Repaired and verified — stale realtime grants.** Project-member removal did not invalidate cached subscriptions; the hub trusted connection-time project grants. Removal now revokes subscriptions after commit. Before event delivery the hub rechecks active identity, current project access, session revocation/expiry and token expiry. The handshake and incoming-message path also reject revoked sessions. Database failures fail closed for event delivery. Regressions cover member removal, inactive users, direct membership deletion, revoked sessions and expired tokens. These tests exercise the real authorization helper and hub with a synthetic socket; a multi-process WebSocket load test was not run.

## Remaining limits — not claimed passed

- **Blocked by environment/configuration:** no live PostgreSQL server acceptance, real SMTP acceptance, external object-storage revocation test, multi-worker restart/queue outage injection or production rollout. Both maintained migration functions were tested on SQLite, not PostgreSQL itself.
- **Not implemented:** expense billing, three-decimal currencies, automatic release of cancelled/credited source reservations, general duplicate-company merging and automatic reconstruction of historical issued snapshots. Existing explicit reconciliation remains review-driven.
- **Accounting restriction:** secondary-seller FAM posting is intentionally blocked without the correct accounting-company context. Legacy/multi-invoice or already posted payment reversals require Accounting review. This audit did not invent accounting policy or auto-reconcile them.
- **Download revocation limitation:** issuing a new attachment URL rechecks current access. An already-issued S3 signed URL remains a bearer capability until its configured expiration (default 900 seconds); immediate external-provider revocation after membership removal is not verified or implemented. Invoice PDFs use authenticated endpoints.
- **Not executed:** every role's complete UI journey, full application shell navigation, exhaustive keyboard testing, stale-route switching under injected latency, concurrent payment/issuance races on real PostgreSQL, worker death during SMTP acceptance, duplicate/out-of-order commercial queue events. Commercial identity and invoice consistency primarily use one database record and transactions; no separate cross-module event consumer was added. Relevant existing event-feed/notification tests passed, but that does not certify all queue failure modes.

The critical commercial lifecycle was verified end to end locally. This is not a blanket certification of every cross-module feature or production deployment.
