# Shared connector catalog

The common catalog is `/connectors`. CRM, Projects, HRMS, Sales and Finance expose the same catalog at their respective `/connectors` routes, filtered by module. Module navigation includes **Connectors & authorization**. Existing Integration Studio links back to the common catalog.

The authenticated Pipedrive app-catalog page was inspected on November 7, 2026, including the Slack description/setup/Authorize panel. The catalog includes its 25 distinct featured/recommended providers, with Mailchimp's sync variants combined into one entry. It also includes the existing governed connector registry. Google Meet uses Google Calendar; Slack's Dealbot uses the existing Slack connector; QuickBooks uses the accounting import/sync workspace; Zapier uses signed webhooks. No duplicate credential store is introduced.

The discovery API returns public provider metadata only. Creation, token storage, verification, execution and disabling remain behind the existing Power Apps credentials permissions, tenant/environment and ownership checks. Merely viewing a module catalog grants no connector execution permission. QuickBooks keeps its existing finance authorization boundary. No external app was installed or authorized in Pipedrive.

New read-only adapters: Calendly account verification, Zoom user verification/meeting listing, PandaDoc document listing. Tokens/API keys use the existing encrypted vault. These adapters do not implement automatic event synchronization, meeting creation, contract sending or e-signing. Live verification requires the user's provider account; tests use synthetic credentials and mocked responses. OAuth browser setup for these three providers is not implemented; they accept an authorized token/API key.

The 11 supported marketplace connectors now use the existing authorization vault, request journal and native import workspace for working module workflows. Eight have OAuth: Facebook Lead Ads, Mailchimp, DocuSign, Trello, Zendesk, LinkedIn Lead Forms, Klaviyo and Apollo. ActiveCampaign and Surfe retain documented API token authorization; CloudTalk retains its API key pair. Existing authorized-token connections remain supported.

OAuth application configuration is server-side: `POWER_FACEBOOK`, `POWER_MAILCHIMP`, `POWER_DOCUSIGN`, `POWER_TRELLO`, `POWER_ZENDESK`, `POWER_LINKEDIN`, `POWER_KLAVIYO` and `POWER_APOLLO`, each with `_CLIENT_ID` and `_CLIENT_SECRET`. Set the exact `POWER_OAUTH_REDIRECT_URI` to `BACKEND_PUBLIC_URL` plus `/api/v1/power-apps/integrations/oauth/callback`. HTTPS is required outside tests. Missing application configuration returns an explicit setup error. Provider approval/entitlements and real account consent remain prerequisites; no live grants have been created. Mailchimp discovers its account data centre; DocuSign binds the chosen account and API host. Refresh is supported when the provider issues a refresh token; Mailchimp tokens have no expiry, while expired Meta tokens require reconnection.

Each connector has a resumable incoming sync action. Jobs checkpoint each page, fingerprint external records, lease concurrent work, retain native import receipts, support pause/resume and optionally run in the existing follow-up worker. Automatic import creates valid new records and skips existing identities, preserving native edits. Changed existing records and invalid mappings remain available in the existing import workspace for deliberate review. This is scheduled inbound sync plus confirmed outbound workflows, not unconditional automatic two-way overwriting.

- Facebook Lead Ads and LinkedIn Lead Forms import native CRM leads. Select the source form/owner and map LinkedIn question IDs to native name/email fields.
- Mailchimp, ActiveCampaign, Klaviyo and Apollo import native CRM contacts and upsert native contacts to the provider. Mailchimp creates new contacts unsubscribed and preserves existing consent; Apollo requests provider deduplication.
- CloudTalk imports native CRM contacts and creates call-centre contacts from selected native contacts. Existing call-history reads remain available; calls and messages are not initiated.
- Trello imports cards as native project tasks in a chosen accessible project and creates cards from native tasks.
- Zendesk imports support tickets as native CRM activities and creates tickets from selected activities, using a private initial comment.
- DocuSign imports envelope status as native CRM activities and creates draft envelopes from a native contact and provider template. Drafts are not sent or signed automatically.
- Surfe starts contact enrichment with explicit credit approval and imports enrichment results. Result retrieval is treated as credit-consuming. Failed requests require a separately confirmed reviewed retry before a new credit-consuming attempt; uncertain writes never silently replay.

The shared catalog and module catalogs expose **Sync & native module workflows**. Integration Studio exposes the same component. Native source selection reuses CRM record visibility and project access checks. Outbound actions require connection write opt-in, provider write scopes, a current native-record preview hash, confirmation and a durable idempotency key. Native edits invalidate stale previews. Jobs and credentials remain owner/company/environment/branch scoped. No duplicate credential store, import engine or worker queue is introduced.

Dedupely and Pipedrive Nova are explicitly marked **Provider API access unavailable**, with no executable authorization button. The user confirmed there is no partner developer account or API documentation. Dedupely's developer API listing redirects to a product page; Nova is documented as a built-in Pipedrive feature. A verified external endpoint/authentication contract is still required for these two; no endpoint, credential flow or successful connection is fabricated. See [Dedupely product](https://dedupe.ly/product) and [Pipedrive Nova meetings](https://support.pipedrive.com/en/article/nova-meetings).

Validation: the marketplace/provider/import regression passed **501 tests**; the final OAuth suite passed **10 tests** (including downscoped-grant rejection) and sync suite passed **35 tests**. Controlled provider fixtures cover all 11 incoming sync-to-native workflows, duplicate prevention, scheduler recovery, native edit preservation, all nine outgoing workflows, confirmation and stale-preview checks. OAuth tests cover all eight consent/callback flows, encrypted token storage, replay rejection, refresh or reconnection behavior and provider header contracts. Real local TLS tests cover all 11 authorization checks and all nine outbound actions, including idempotent replay. The TLS certificate/socket routing exists only in tests; application egress checks are unchanged. TypeScript and production build pass. These checks do not certify live vendor credentials, provider app approval or production account entitlements.

The disposable local QA runtime is `backend/scripts/serve_connector_catalog_qa.py` on port 1571, with frontend port 5223. It uses synthetic credentials and a provider fixture that rejects traffic outside its fake account. Original development servers and existing user changes are preserved. No external messages, calls, live charges or remote deployment were performed.
