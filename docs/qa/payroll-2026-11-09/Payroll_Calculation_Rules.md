# Actual payroll calculation rules

Inspected 9 November 2026 before interpreting results. Source: `backend/app/crud/crud_payroll.py`, `backend/app/api/v1/payroll.py`, payroll models/schemas and existing tests. These describe implementation, not newly approved HR policy.

- Annual CTC / 12 is monthly salary. Historical salary versions are now weighted within the employee's actual employment interval in the period. Salary versions wholly before joining or after exit do not affect that interval; the resulting monthly equivalent is prorated once by employed calendar days / full-period calendar days. Basic defaults to 40% of monthly CTC when missing/zero; HRA defaults to 50% of basic when missing/zero. A zero basic/HRA therefore currently means fallback, not an explicit zero component.
- Joining and exit are inclusive, clamped to the period. Monthly salary and basic/HRA are multiplied by employed calendar days / period calendar days. No employed dates means no record.
- The working-day denominator follows employee/company/pay-group calendars in the main engine. Monthly LOP deduction = prorated monthly earnings / working days × LOP days. The tested engine does not use a fixed 30-day divisor. Do not apply the brief's 30-day examples to it.
- An approved attendance input supplies working, payable and LOP days. Without that input, no raw attendance means fully payable. Once raw attendance exists, Present/WFH contribute 1 and half-day contributes 0.5; unpaid/missing statuses contribute zero. Payable is capped at working days; LOP is the remainder.
- Reconciliation counts Monday–Friday working dates and approved leave calendar overlap, recognizes unpaid leave by leave type/name, and adds approved manual LOP adjustments. The follow-up fix unions half-day intervals instead of summing duplicate requests. First/second halves remain distinct, full day covers both; legacy half-day rows without a half-period retain a first-half fallback. Deleted, pending, rejected and cancelled leave do not contribute. Payable = max(0, working days − unpaid leave − manual LOP). Missing attendance alone does not create LOP in that path. Calendar inclusion policy was not changed.
- LWP sync uses the same leave-interval union. Explicit absent attendance contributes only intervals not already covered by approved paid/unpaid leave. Cancelling the last unpaid leave clears an existing synced entry/input to zero rather than leaving stale LOP. The preview still omits zero-day entries. Sync, reconciliation, input upsert and manual-input approval reject locked/paid payroll periods.
- Daily wages multiply rate by paid days. Hourly/lecture/class/delivery/trip/shift/piece/unit modes multiply configured rate by default units. Commission multiplies base by percentage, with a rate×units fallback when zero. Invoice pay uses configured invoice amount or rate×units. Mixed mode adds unit pay to the monthly calculation.
- Approved manual earnings, overtime and encashment increase gross. Approved manual deductions and salary advance recoveries increase deductions. Approved unlinked reimbursements in the period increase net separately. Net = gross − deductions + reimbursements. Negative net is retained and marked anomalous, rather than automatically clamped to zero.
- Statutory values use effective configured PF/ESI rules and employee profiles, plus matching state/month PT/LWF slabs. The test fixtures explicitly set rates/caps; these tests do not establish legally applicable rates. No statutory submission was executed.
- Decimal money rounds to two places using the current Decimal context (half-even). “Nearest Rupee” rounds to an integer using half-even, then two places; “No Rounding” still rounds to two decimal places. The independent QA calculator explicitly selects half-even.
- Run identity includes period and organization/branch/department/pay-group/category. Existing calculated runs may be recalculated; approved/locked/paid runs cannot. Salary assignment checks period locking and closes the active salary before adding a replacement. Approval/locking and payslip publication have separate gates.
- Historical run eligibility follows inclusive employment dates, not current employee status alone. An employee whose exit predates the period is excluded; a currently inactive former employee can still be eligible for an earlier employed period.
- Recalculation retains paid/recovered one-time inputs already linked to the same employee and run. Inputs consumed by another run remain excluded. PostgreSQL generation takes a transaction-scoped advisory lock for the established run identity before lookup, plus a row lock for existing runs. Approval/locking also locks the run row and refreshes its status. No table/index/history migration is introduced.
- Leave submission rejects requests before joining or after exit, half-day requests covering multiple dates, and half-days when disabled on the selected leave type. Existing overlap and balance checks still apply.

## Configurable policy closure

The four blocked cases and two unsupported options are now implemented and verified. Payroll_Policy_Implementation.md defines the defaults, alternatives, formulas, activation and frozen-history behavior. These rules apply to published effective-dated pay-group policies; legacy descriptions above remain applicable to unpublished groups. Existing statutory rounding is retained.

Independent oracle: `backend/tests/payroll_expected_calculator.py`. Salary calendar history and LOP/threshold tests call actual production services and compare against independently computed Decimal values.

PostgreSQL follow-up: local PostgreSQL 17.11, full application migration chain, separate committed multi-connection fixtures, real-API desktop/phone workflows and final-settlement tests. The execution report/CSV track all six policy requirements as resolved grouped coverage, separate from automated case counts. Approved unlock requests permit controlled correction back in calculated state; earlier calculation snapshots are retained and checked in the browser workflow.

Historical wage modes/rates are now selected from the salary interval overlapping the requested period, rather than the latest active assignment. Readiness uses the same effective-date range. Future monthly/hourly/daily switches cannot alter an earlier period. LOP reconciliation/feed cap deductions at their working-day denominator; negative correction adjustments cannot create negative LOP.
