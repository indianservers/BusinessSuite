Local optimized default and module performance — 2026-11-04

Normal URL: http://localhost:5173. start-frontend.cmd now runs npm start,
which fingerprints the frontend sources, type-checks and builds when changed,
then serves the optimized dist with the existing backend proxy on port 1534.
Unchanged starts skip compilation. Explicit development mode is available via
start-frontend-dev.cmd on port 5174. No deployment or permission grants changed.

Changes
- Retained lazy route/preview/team-workspace loading and the shared record cache.
- Batched payroll unpaid leave, attendance and salary calculations instead of
  querying each employee separately; eagerly loaded guided payroll dependencies.
- Payroll only fetches inputs/statutory/tax/tools data when its tab opens.
- Batched PMS destination membership counts, visible avatars and leaders.
- Follow-up customer options reuse native CRM/SRM/PMS authorized company queries.
- Batched CRM branch-label ownership/name lookups; writes bypass read caches.
- Removed an unused CRM dashboard contacts request.
- Cache identity uses authenticated primary role rather than module display role;
  tenant, branch, actor, session and live grants remain part of the identity.
- PMS combines overlapping detail refreshes for the same workspace/role.

Remaining findings / limits
PMS board home still takes roughly 5.7–6.9 seconds to finish all requests in these
runs; its workspace/member/overview and background refreshes remain a hotspot.
Power Apps connectors measured 5.2 seconds during the full navigation audit and
2.5 seconds on an isolated reload. Other audited pages mostly settled in 1–4s.
The legacy PMS workspace 1 chat conversations endpoint returns 404 while its
workspace list and board remain readable; this needs separate membership/legacy
organization reconciliation. Chat authorization was not relaxed to conceal it.
This is broad module/page and targeted workflow coverage, not certification of
every route, financial posting, external provider, or every possible role combination.
