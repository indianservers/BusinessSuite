3. Additive schema and API
No new business tables. Add collection_hold, collection_hold_reason and
collection_resume_at to srm_invoices. Add nullable request_id and a unique
(receipt_id, request_id) constraint to srm_receipt_allocations. These close
verified dispute-control and retry gaps while retaining existing rows.
Both migration histories call the same helper:
  20261104_063_collections
  pg_20261104_079_collections
New API: PUT /api/v1/srm/collections/{invoice_id}/control, restricted to existing
collection-create/admin permissions and the existing invoice visibility query.
It records a reason and audit/history entry for hold/resume/scheduled resume.

4. Workflows implemented or corrected
- Retry-key allocation returns the existing allocation; changed payload => 409.
- Cancelled/reversed receipts cannot be allocated; positive cent precision is
  enforced for receipts, allocations and direct payments.
- Direct payment retries reject reuse of a key with changed payment details.
- Disputed collections pause reminders and permit manual or scheduled resume.
- Queued reminders recheck current invoice, billing recipient and hold before
  provider submission. Paid/stale messages are cancelled; holds defer delivery.
- Invoice due rules exclude drafts, pending approvals, settled documents and
  contacts outside billing/primary roles.
- Shared CRM follow-up notifications stop for terminal quotation states and
  noneligible invoices; follow-up records/history remain available.
- Aging excludes unissued/cancelled/written-off invoices, keeps currencies
  separate and accumulates Decimal amounts.
- New quote revisions retain prior snapshots, clear prior approval/sending/PDF
  metadata, supersede pending approvals and add audit/timeline entries.
- Revision snapshots no longer recursively embed earlier version snapshots.
- Quote discounts/tax round per line with ROUND_HALF_UP and validated bounds.
- Regenerated quote PDF paths are unique and versioned; old files are retained.
- Collection context loading and linked follow-up source checks use batching.
- SRM settings reads explicitly apply tenant scope.
- Existing collections UI now exposes payment method/date on desktop as well as
  mobile, collection hold/resume controls and scheduled resume, with cache refresh.

5. Cross-module integration
All changes extend existing canonical records. Existing connected-commercial
tests exercise customer snapshots, shared project/Sales invoice visibility,
payments, authorized delivery and financial posting. Milestone billing continues
to generate the same SRM invoice using an explicit source mapping. No separate
CRM/Sales invoice engine or payment ledger was introduced.
FAM-authoritative consolidation across EVERY direct finance mutation is NOT
complete; do not infer that from the reused FAM posting test.

6. Reminder configuration
Use the existing Customer communications automation editor. Added presets for
3 days before due, due date and 3 days overdue. Presets remain drafts until an
authorized user configures/activates them. Existing invoice.due rules support
conditions.days_before (3, 0, -3, -7, -15, -30), consented channels, quiet hours,
weekdays, reply stops and durable delivery keys. Existing workers provide actual
provider dispatch and outcomes; this work sent no live customer messages.
Internal salesperson/accounts/manager escalations for the full default policy
have not been implemented as an automatic six-stage policy.
