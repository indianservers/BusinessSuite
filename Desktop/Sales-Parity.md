# Sales and POS parity checklist

The existing desktop Sales & POS form only routes to web pages. The web routes are listed in `frontend/src/apps/srm/routes.tsx`. The audit below records workflow groups and current coverage. The initial source inspection did not find a listening web development server on ports 3000, 4173, 5173, or 8000. Live interaction and layout comparison are outstanding.

## Scope and source of truth

- [ ] Resolve the signed-in user, selected company, branch authority, module action and row scope before loading or modifying Sales records. SRM's native permission and assignment rules are in `backend/app/apps/srm/access.py`, and company and branch ownership enforcement is in `backend/app/branches/boundary.py`. Pack-specific records may additionally require context ownership in `business_pack_record_ownership` and the operation permissions in `backend/app/business_packs/request_operations.py`. Company-level access alone cannot authorize branch-owned or pack-private records.
- [ ] Exercise branch isolation, denied actions, stale selections and legacy records with missing ownership. Honor `deleted_at` for operational lists.
- [ ] Share customer, vendor, contacts, warehouse, catalog, and product pricing records with their owning modules. Confirm branch sharing applies only to resource types declared shared in the web branch policy.
