# Project Management parity checklist

The desktop originally opened web routes for the workspace, workspace directory and My Work. All three entry points now open WinForms screens. The route inventory comes from `frontend/src/apps/project-management/routes.tsx`. PostgreSQL entities are defined in `backend/app/apps/project_management/models.py`. The local web UI was unavailable on the checked ports (3000, 5173 and 8000). Existing reference screenshots are under `frontend/docs/qa`.

## Projects and workspaces

- [ ] Project portfolio and classic list. `ProjectsList.tsx` reads accessible non-deleted, non-task-collection projects. `api/router.py:list_projects` calculates task and milestone counts, team, owner, client and capability flags. The list provides search and status/priority/workspace filters, attention and overdue views, grouping, board/timeline/calendar and alternate views, adjustable columns, pinned preview, recent and starred records, personal/shared saved views, and export. Distinguish initial loading, no records, no filter matches and error/retry.
- [ ] Project preview, create and edit. `CreateProjectPage.tsx` uses Additional details, Products & services and Planning & ownership steps, workspace selection for Owner/Admin, project key, name, brief/description, status, priority, dates, optional budget and custom fields. The UI preserves create drafts, supports create another and autosaves changes during edit. The API uppercases keys, enforces organization uniqueness even for archived/deleted rows, checks workspace and active owner/manager access, fills owner and legacy dates, validates supplied custom fields, creates a Manager membership for the actor, and writes project activity. Edit rejects reversed dates, invalid name/status/priority and cross-company clients, stamps first activation/completion dates, and records prior values and status/budget changes. The editor and write service must reject stale updates.
- [ ] Project actions. `ProjectsList.tsx` and `DuplicateProjectDialog.tsx` offer create task, copy link, duplicate, inline updates, bulk updates, archive and move to Trash. API edit permission limits writes. Archive toggles `is_archived`; Trash marks `deleted_at` and keeps children. Restore checks scoped authority and restores access to children without modifying them. Clone must create distinct child records and honor the selected options. See `test_pms_project_trash.py`, `test_pms_project_portfolio.py` and `test_pms_project_access.py`.
- [ ] Project detail. Overview and memberships, board, timeline/Gantt, milestones, files, notes, risks, reports, analytics, communication and billing have project-scoped routes. Review each tab independently against its page, API and workflow tests before implementing.
- [ ] Workspace directory and workspace landing. `WorkspaceDirectoryPage.tsx`, `WorkspacesPage.tsx` and `workspaces.py` expose memberships, owner, project/task counts and workspace navigation. Workspace role controls access. `pms_workspace_archives` suppresses active views without deleting records. Owner/Admin can manage membership; invitation creation and activation enforce email, bounded expiry, revocation, one-time use, and existing account protection. See `test_pms_workspaces.py`, `test_pms_workspace_activity.py` and `test_pms_workspace_migration.py`.

## Access boundary

`access.py` checks organization, workspace archive, workspace membership, legacy project membership and PMS global permissions. Workspace Owner/Admin manage projects, Member can work on tasks, and Guest can browse. Legacy projects use global permissions, manager/employee relationship or project membership. `people_management.py` resolves organization admin authority. `backend/app/access/service.py` resolves active company membership, policy status, managed grants and roles, company entitlements and branch access. The desktop must derive these from an authenticated actor. An environment company/branch ID defines a selected scope and supplies no permission by itself.
