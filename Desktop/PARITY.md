# Desktop parity checklist

Module audits are tracked in [CRM](CRM-Parity.md), [PMS](PMS-Parity.md), [Sales and POS](Sales-Parity.md), [HRMS](HRMS-Parity.md), [Appointments](Appointments-Parity.md), and [Communication Center](Communication-Parity.md).

## Shared foundation

- [x] Company and branch selectors. The web UI uses `frontend/src/components/suite/CompanySwitcher.tsx` and `BranchSwitcher.tsx`. The server resolves membership in `app/access/service.py` and branch policy, home branch, explicit grants and archive status in `app/branches/service.py`. Tests include `test_branch_access.py` and `test_branch_access_fresh_projection.py`. Desktop verifies the configured server and changes the current session scope through Tools → Settings. Tested switching branches in the running desktop app and hiding unauthorized choices in the restricted-login probe.
- [ ] Native company and branch administration, including grants, branch lifecycle, and audit.
- [ ] Shared permissions. Web grants can come from native roles, managed company policy, module roles, branch grants and entitlements. Desktop derives the actor from the authenticated PostgreSQL login and verifies active company membership and branch access. Module grant checks and per-record scope remain module-specific. Suite MFA and SSO are unavailable through the desktop sign-in path.
- [ ] Employees. The native Employee Directory and Appointments provider lookup use the existing employees table. The remaining directory and employee administration actions are listed in [HRMS parity](HRMS-Parity.md).
- [ ] Companies, contacts, customers, vendors, channel and custom field editing. See CRM for action, validation, linked record and duplicate rules. CRM and Sales use the existing shared records. The web customer identity checks are covered in `test_customer_identity.py`; company masters use `business_packs/company_master_core.py`. Shared customer/vendor and channel action coverage is pending.
- [ ] Categories, subcategories, products and services. The web `CatalogPage.tsx` uses `app/shared/catalog.py`, `catalog_models.py`, `catalog_categories.py`, `catalog_branches.py` and `service_category_links.py`. Tests include `test_catalog_categories.py`, `test_pos_shared_catalog.py` and `test_catalog_branch_reuse.py`. Desktop Shared Business Data → Products and Services lists the canonical `srm_products` rows with category paths, branch availability, search and archive status. Repository proof includes the same service used for an Appointments booking. Catalog Categories supports add, rename and remove for categories and subcategories with a versioned PostgreSQL save. Verified category rename, subcategory persistence, attached offering label updates, branch-specific offering visibility, duplicate and stale edits and assigned-category removal rejection. Extended offering fields, branch reuse, price lists, and workspace-specific or pack-specific scope remain open.
- [x] Products and Services imports UTF-8 JSON, CSV, TSV, and Excel workbooks for the selected branch. The native fixed-column preview and atomic writer follow the `CatalogPage.tsx` import action, `ItemInput` and `import_items` in `app/shared/catalog.py`, and `test_import_export_validation_and_atomicity`. Column mapping follows `ImportWizard.tsx`, `transfer.ts`, and `tabular_files.py` for suggested headings, editable destinations, skipped columns and a product or service default. JSON mapping uses the union of keys across rows and preserves mapped numbers, scalars, arrays and objects. Workbooks support worksheet selection and header rows 1–50, retain formula text without evaluating it, and apply the expanded ZIP limits. The parser validates the 2 MB and 500-offering limits. The batch creates ordinary product and service records, including archive state, category IDs, prices, tags, image references and scalar custom fields. Multi-branch, workspace and specialized offering imports remain open.
- [ ] Common grids and editors. Existing Telerik designer-defined CRM grids are the baseline. Verify columns, empty results, errors, filter behavior, export and designer editability on each form. Shared lookup/editor extraction is pending.

The catalog export audit followed `CatalogPage.tsx` and `ExportButton.tsx` through the `/catalog/export` handler and its all-status, paged catalog query. The native Products and Services toolbar exports active and archived offerings to JSON, CSV or Excel using the same visibility rules as the native Sales catalog. A .NET Framework 4.8 PostgreSQL probe verified branch-specific rows, archived rows, prices and metadata, omitted record IDs and versions, and preservation of the destination on cancellation. The CSV probe also verified Unicode, quoted multiline fields, JSON cells and spreadsheet formula protection for free-text columns. An independent workbook reader verified XLSX column addresses beyond Z, typed prices, Unicode, multiline text and formula-like strings stored as text. The Leads workbook regression passed with the same writer. A restricted PostgreSQL login with a managed view-only action could open the list and was denied all three formats before a file was created. Workspace and pack-specific exports remain open.
